# PWX-0003: Use a functional-core, imperative-shell architecture

**Status:** Accepted
**Date:** 2026-11-17

## Context
The password generation logic is the security-critical part of the project
and must be thoroughly tested. Code that touches the DOM, clipboard, or
browser APIs is harder to test. Later milestones will add more entry points
(right-click menu, content script) that all need the same generator.

## Options considered
1. **Generation logic inside the popup script.** Fewer files, but hard to
   test and impossible to reuse.
2. **Functional core, imperative shell.** A pure generator module wrapped by
   thin UI code.

## Decision
- **Functional core:** `generator.ts` is pure. It takes options and returns a
  password, with no access to the DOM, clipboard, or storage.
- **Imperative shell:** `popup.ts` handles user events, the DOM, and the
  clipboard, and calls the generator.
- **Dependency injection:** the generator receives its random source as a
  parameter, defaulting to `crypto.getRandomValues()`. Tests can pass a
  predictable fake source.
- **One-way data flow in the popup:** a single state object holds the current
  options and password. Every user action updates the state, then one
  `render()` function redraws the popup from it.

## Consequences
- The generator can be unit-tested in isolation, including edge cases like
  rejection sampling, using a fake random source.
- Later entry points reuse the generator without changes.
- The popup can't show stale values, because it is always drawn from one
  source of truth.
- Passphrase mode (a later milestone) can be added as a second generation
  strategy behind the same interface.
