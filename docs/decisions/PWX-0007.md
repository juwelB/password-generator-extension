# PWX-0007: Popup behavior defaults

**Status:** Accepted
**Date:** 2026-11-17

## Context
Several smaller behaviors in the v1 popup need defined rules so the
implementation and tests agree on them.

## Decision
- **Length range:** 8 to 32 characters. Below 8 is too weak to offer. At 32
  characters with all character types, a password has roughly 200 bits of
  entropy, far beyond what any attack can brute-force, so longer lengths add
  no practical security and are more likely to hit site maximums.
- **Character types:** at least one must stay selected. The last remaining
  checkbox cannot be unchecked, which prevents the invalid state instead of
  showing an error.
- **Changing an option:** regenerates the password immediately, consistent
  with the one-way data flow in PWX-0003.
- **Copy feedback:** the Copy button reads "Copied!" for about 2 seconds,
  then reverts.
- **Ambiguous characters** (`0/O`, `1/l/I`): included in v1. Reducing
  ambiguity is a planned improvement: an "exclude ambiguous characters"
  toggle will be added in a later version through its own ADR.
- **Entropy display:** shown in v1 as an estimate in bits (for example,
  "≈ 95 bits").

## Consequences
- The generator's input validation and the popup's controls follow the same
  rules, which keeps tests straightforward.
- Deferring the ambiguous-characters toggle keeps the MVP small, at the cost
  of occasional hard-to-read passwords when typed by hand.
