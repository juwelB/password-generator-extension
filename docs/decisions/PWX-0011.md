# PWX-0011: Use Oxlint instead of ESLint

**Status:** Accepted
**Date:** 2026-11-19
**Supersedes:** The linting choice in PWX-0001

## Context
PWX-0001 chose ESLint for linting. TypeScript support in ESLint comes from
typescript-eslint, which depends on the JavaScript-based TypeScript compiler
API. TypeScript 7 rewrote the compiler in Go and does not yet provide that
API, so typescript-eslint cannot be installed alongside `typescript@7`.

## Options considered
1. **Downgrade to TypeScript 6** so typescript-eslint works. Gives up the
   faster compiler and adds a version to migrate away from later.
2. **Install TypeScript 6 alongside 7** just for linting. Two compilers in
   one project, and more setup to explain.
3. **Use Oxlint,** a Rust-based linter that parses TypeScript itself and has
   no dependency on the TypeScript compiler.

## Decision
Use Oxlint (option 3), with its default rules. Prettier remains the
formatter, as in PWX-0001.

## Consequences
- Linting works with TypeScript 7 today, and runs very quickly.
- Oxlint's default rules focus on likely bugs. Type-aware rules (which need
  type information) are not used in v1.
- If typescript-eslint gains TypeScript 7 support later, switching back is
  possible through a new ADR.
- CI runs `format:check` and `lint` before the tests, so badly formatted or
  lint-failing code fails the build.
