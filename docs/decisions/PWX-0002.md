# PWX-0002: Limit v1 scope to a popup, with no stored passwords

**Status:** Accepted
**Date:** 2026-11-17

## Context

The full vision includes in-page suggestions, a right-click menu, saved
settings, and passphrase mode. Building all of it at once delays having a
working extension. Separately, any feature that stores generated passwords
turns the project into a password vault, which is a much larger security
responsibility.

## Options considered

1. **Full feature set in v1** (popup, right-click menu, automatic field
   detection, saved settings).
2. **Popup only in v1**, with other features added in later milestones.

## Decision

Version 1 is a popup that generates a password, regenerates it on demand,
and copies it to the clipboard. The user pastes it manually.

- No background service worker or content script in v1.
- No `chrome.storage`: settings reset each time the popup opens.
- Generated passwords are **never stored**, in v1 or any later version.
  No history and no logs.
- The extension requests no special permissions in v1.

## Consequences

- A usable extension exists after the first milestone.
- The minimal permission footprint is easy to justify to users and reviewers.
- Users must re-select options each time until saved settings arrive in
  milestone 2.
- Never storing passwords keeps the extension out of password-vault territory
  permanently; changing that would require a new ADR.
