# PWX-0008: Throw a typed error on invalid generator input

**Status:** Accepted
**Date:** 2026-11-17

## Context
The generator must handle invalid input, such as a length outside 8 to 32 or
no character sets selected. TypeScript types are erased at runtime, so the
type system alone cannot prevent bad values from reaching the generator.

The popup already prevents invalid input: the length slider is limited to the
valid range, and the last selected character type cannot be unchecked
(PWX-0007). Invalid input reaching the generator therefore means a bug in the
code, not a user mistake.

## Options considered
1. **Return an error value** (a result object with either a password or an
   error). Common in Go. Forces every caller to check the result.
2. **Throw a typed error.** Callers using valid input need no extra checks;
   bugs fail loudly.
3. **Silently correct the input** (for example, clamp length to the range).
   Hides bugs and produces passwords the caller didn't ask for.

## Decision
Throw a `GeneratorError` (option 2). It extends the built-in `Error` and has
a `code` property: `INVALID_LENGTH`, `NO_CHARACTER_SETS`, or
`UNKNOWN_CHARACTER_SET`.

## Consequences
- A bug that sends bad input fails immediately in tests instead of producing
  a wrong password.
- Tests can check the specific `code`, not just that something failed.
- Callers don't need to handle errors for normal use, since the popup can't
  produce invalid input.
- Later entry points (right-click menu, content script) must also send valid
  input, or catch `GeneratorError` if they accept settings from elsewhere.
